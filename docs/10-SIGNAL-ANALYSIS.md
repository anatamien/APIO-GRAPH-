# Experimental signal processing — APIO GRAPH 1.2

The Mathematics panel provides baseline correction, peak detection and region integration. Inputs are complete source or derived datasets. A hidden source remains a valid input. Preview is temporary; Add result / Apply is one undoable command. Changing parameters does not automatically start a calculation. Cancellation terminates the analysis Worker, and generation/input checks reject late or obsolete results.

## Baseline correction

- **Anchor points:** add/drag points on the chart or enter exact X/Y; remove points in the panel. The baseline is piecewise linear, evaluated at each original observation X. Nodes must cover the signal; extrapolation requires an explicit checkbox. Source rows and Y remain unchanged.
- **Polynomial background:** degree 0–3, fitted only to observations inside the entered background intervals. A single-point interval selects one observation X. Chart picking adds an observed background X. Overlapping intervals merge without duplicating observations. Existing centered/scaled Householder QR is used; no peak region is automatically classified as background.
- **AsLS:** asymmetric least squares with a second-difference penalty, following [Eilers and Boelens (2005)](https://prod-dcd-datasets-public-files-eu-west-1.s3.eu-west-1.amazonaws.com/dd7c1919-302c-4ba0-8f88-8aa61e86bb9d). Each iteration solves `(W + λ DᵀD) z = W y` with three-diagonal Cholesky storage. Time is O(iterations × N), workspace O(N); no dense N×N matrix. Y is normalized before solving. Weights are p above the estimated baseline and 1−p otherwise. Stop when weights stabilize or relative L2 change is below tolerance; reaching the iteration limit produces a warning, not a false convergence claim. The estimated baseline is not an exact physical background.

AsLS supports uniform increasing X; local step tolerance is 0.1% plus floating-point spacing allowance. It does not silently resample irregular measurements. λ is limited to 10⁻⁸…10⁹, p to 10⁻⁶…1−10⁻⁶, iterations to 1…200 and tolerance to 10⁻¹²…0.1. Use manual or polynomial correction for irregular X. Unordered/duplicate X requires explicit working-copy sorting/aggregation where needed. Mean/median aggregation never rewrites raw rows. Nonfinite values and uncovered ranges are rejected explicitly.

Preview displays baseline and corrected signal. Save baseline, corrected signal, or both as independent datasets/calculation nodes. Both are committed together; colors, visibility and subsequent processing are independent. Recalculation reuses a shared baseline solve when both output nodes have identical numerical parameters and source, without losing either result's identity or style.

## Peaks

Search maxima or minima over all X or a selected interval. The Y threshold is an absolute lower bound for maxima, upper bound for minima. Prominence is the vertical distance from the extremum to its topographic contour; it is distinct from the Y threshold. The distance filter is expressed in physical X units or integer observation counts. Higher-amplitude peaks win distance conflicts, with earlier positions breaking exact ties. A flat maximum uses the middle observation, rounded toward the earlier observation for even plateaus.

Widths are measured at `peak − relativeHeight × prominence` (sign reversed for minima). The default 0.5 is **half-prominence width**; it equals FWHM for an isolated peak on a zero baseline. Crossing X is linearly interpolated on the actual, potentially irregular X grid. Missing crossings, incomplete edge peaks or undefined prominence produce null/“Undefined”, never fabricated zero widths. A prominence threshold applies to complete peaks; incomplete edges can be explicitly included. Width filters exclude undefined widths and report their count. Threshold/distance exclusions are also counted.

The prominence implementation uses nearest strictly greater neighbors, range minima and logarithmic crossing queries. Equal-height peaks do not cause repeated full-array scans. All results remain in the project and virtual table; screen-only density reduction and a batched SVG path keep the chart responsive. Clicking a row highlights/centers the peak without data edits or a history command. Copy uses selected rows, or all rows when none are selected. CSV/TSV export always includes the complete table. Numeric text uses round-trip decimal precision with decimal points; undefined metrics are empty export fields.

See the primary definitions in [SciPy prominence](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.peak_prominences.html), [width](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.peak_widths.html) and [peak detection](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.find_peaks.html) documentation. Independent oracle fixtures are generated by `scripts/signal-references.py` using NumPy/SciPy; these packages are optional test tools, not application dependencies. The AsLS oracle uses sparse LU, independent of the application's banded Cholesky solver.

## Region integration

Move either X boundary on the chart or enter X numerically, including outside the current view. Preview/Apply use full numerical arrays, not screen geometry. The signed trapezoidal integral shares the existing compensated integration routine. Both selected boundaries are linearly interpolated; integration never extrapolates outside source/reference coverage. With a baseline, integrate `signal(x) − baseline(x)` over the **union of both piecewise-linear X grids**, with exact interpolated boundary values. No hidden vertical shift or unit conversion is performed. Signal and baseline X/Y units must match.

Signed area is primary. A separate integral of absolute magnitude splits segments at zero crossings. Units are X×Y; range, sources, reference type, value and provenance are saved. An area is a scalar result with independent fill color, opacity, visibility and optional label in Data and results. It does not create a fake data curve. Changes to either source invalidate it and its recomputation follows the dependency graph.

## Projects and exports

The application version is 1.2.0. The project schema is **1.1.0**: calculation kinds `baseline`, `peaks`, `area`, optional structured peak measurements and result-display settings. The original 1.0 schema remains available. Loading a valid 1.0 project upgrades the in-memory schema metadata only, retaining coordinates, IDs, source metadata, styles, annotations and original creation version. The source file is not rewritten until the user saves. Older application versions do not understand the new result types.

Existing limits remain 1,000,000 points per dataset and 200 MiB per project/exported data file. Peak measurements are limited to 1,000,000 entries per calculation. Large result tables can therefore reach the file-size limit; saving reports an error rather than truncating results. Immutable peak tables are mirrored once into the serialization Worker and reused for appearance-only saves.

Confirmed visible results participate in SVG/PNG/JPEG and strict black-and-white export. Area uses hatching in strict B/W; labels go through the existing overflow preflight. Draft nodes, boundaries, highlights and preview geometry are never exported. Screen reduction affects only geometry; final SVG uses all confirmed peak positions and complete source curves. UI themes preserve existing application behavior; custom series/result colors and stored numerical values remain unchanged.

Area screen geometry uses the complete ordered/aggregated working grid before any display reduction. Large hidden or unordered inputs are prepared in a cancellable Worker with an extrema index; input copying and result hydration yield to UI events. Until the exact grid is ready, no estimated fill is shown. Navigation then reuses that immutable grid/index; duplicate observations never acquire different weights due to display sampling. The cache is temporary and is not written into the project.
